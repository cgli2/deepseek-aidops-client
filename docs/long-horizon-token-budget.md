# 长任务累计 token 预算

`HARNESS_LHA_TOTAL_TOKENS` 默认值为 `0`，表示不设置累计 token 硬上限。
需要限制累计消耗时，可显式设置正整数；此额度由同一工作区内一批活跃任务共享，全部结束后下一批任务重置额度。

原来的默认值 `10000000` 会按每次请求的上下文估算量和输出预留量累计扣减，长任务可能在交付前耗尽。所有模型共享此控制平面额度，因此切换模型无法解决问题。

更新并重启应用后，未配置上限或配置为 `0` 时，旧 `budget.json` 中耗尽的余额不再阻断请求，无需删除工作区状态。如果环境变量仍显式设置了正整数，可将它改为 `0`。已终止的任务不会自动复活，需要在原会话中继续任务。

此变更保留请求/token 速率限制、429 退避、取消机制及交付验收。它消除本地默认累计额度导致的中断，不改变上游模型服务的配额或可用性。

回归测试：`cargo test -p harness-runtime --test lha_p2` 和 `cargo test -p harness-runtime --lib lha::rate_limit::tests`。
