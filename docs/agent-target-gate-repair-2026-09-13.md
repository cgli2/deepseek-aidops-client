# Agent 定位后无法修改：日志分析与修复

## 证据与根因

对照用户提供的复制按钮会话及 pasted-text.txt 中的 MarketHubView 会话，执行器存在可以在本地复现的门控矛盾：

1. `record_targets_from_search` 原来跳过首行、只检查随后 12 行，并在收集 8 条命中后退出。宽泛的 copy 搜索先命中 Cargo.lock/build.bat 时，后面的实际实现文件可能被执行器丢弃，即使模型已经看到了该文件。
2. 成功的 fs.read 将工作项推进 ReadyToChange，却不将读取路径加入 confirmed_target_files。于是状态要求编辑，编辑门控却要求再次搜索。
3. ReadyToChange 的模型工具白名单隐藏 search。只修改工具准入函数无法修复模型侧没有恢复入口的问题。
4. 目录锚点被当成访问边界。router/index.ts 引用 views/MarketHubView.vue，并不能让模型读取后者；日志中因此出现修改无关路由、尝试 shell 写入等绕路。
5. fs.write 原先按 inspect 计费，且目标校验与 edit 不一致。

这些是程序行为，不需要用户再回复“写入修改”或解除权限。重复搜索和道歉不能改变门控条件。

## 本次修改

- 解析工具实际返回的全部标准搜索命中，兼容无表头和混合路径分隔符。
- 将成功读取的具体文件记为已检查目标，可直接编辑；失败读取不会确认文件。
- 允许明确文件路径的跨目录读取，目录锚点继续用于导航；文件访问权限仍由工具访问策略检查。
- 定位阶段提供 fs；待修改阶段保留有预算限制的定向 search，模型工具列表与执行门控保持一致。
- fs.write 与 edit 共享写入阶段、只读限制和目标确认规则。
- 保留重复调用限制、阶段预算和实际变更/验证要求。读到文件只代表具备编辑上下文，不代表语义诊断正确，更不代表任务已经完成。

## 回归验证

新增确定性回放：复制按钮的“噪声搜索→读取实现→编辑→验证”；路由到兄弟目录组件；超过旧截断边界的搜索结果；失败读取不确认目标、定向恢复受预算限制、只读任务不能写入。

运行命令：

```text
cargo +stable-x86_64-pc-windows-msvc test --manifest-path harness/Cargo.toml -p harness-runtime --offline --quiet
```

结果：364 项通过、1 项忽略、0 项失败；包含运行时单元测试及工具循环、会话回放、DSML 等集成测试。`git diff --check` 通过。

本次没有调用真实 DeepSeek 服务重跑百轮会话，也没有替换正在运行的桌面可执行文件。确定性回放验证的是执行器状态迁移，不等价于模型端到端成功率测试。日志中裸露 DSML 和 shell 引号错误属于另外的失败表现，不能据本次门控测试宣称全部消除。
